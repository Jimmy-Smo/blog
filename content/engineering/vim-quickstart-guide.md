在终端里打开一个配置文件，敲字却没有输入，按方向键能移动光标，又不知道怎样保存退出。这通常就是第一次遇到 Vim 的体验。

Vim 把“输入文字”和“操作文字”分成不同模式，刚开始需要适应，熟悉以后，改一个词、删一段内容、重复上一次修改都可以用很短的按键完成。入门目标可以很小：独立改完一个文件，再把常用操作带进每天使用的开发工具。

本文以独立 Vim 为基础，后面的工具搭配单独说明差异。官方资料核验于 2026-09-22；基础命令适用于常见的 Vim 8/9，插件界面和 Claude Code 支持的键位以所装版本为准。

## 先花十分钟，完成一次编辑

在终端运行下面的命令，检查是否已经安装：

```bash
vim --version
```

有版本信息就可以开始。找不到命令时，macOS 可以用已安装的 Homebrew 执行 `brew install vim`；Ubuntu/Debian 可以执行 `sudo apt install vim`；Windows 可以从 [Vim 官网下载页](https://www.vim.org/download.php)安装，或者在 WSL 的 Linux 环境中练习。现在不用纠结 Vim 和 Neovim，后者是另一个编辑器项目，基础操作相近，配置和插件生态有差异。

选择一个练习目录，打开一个新文件：

```bash
vim practice.txt
```

按下面的顺序操作。`Esc` 表示键盘上的 Escape 键，`Enter` 表示回车；`dd`、`gg` 这样的写法表示依次按键，`Ctrl+r` 才表示同时按。

1. 按 `i`，进入可以输入文字的状态。
2. 输入 `Hello Vim`，回车，再输入 `I am learning Vim.`。
3. 按 `Esc`，结束输入。
4. 输入 `:w`，按回车，保存文件。
5. 输入 `:q`，按回车，退出 Vim。

重新执行 `vim practice.txt`，看到刚才的两行文字，就完成了第一次编辑。保存、退出的操作来自 [Vim 用户手册的入门章节](https://vimhelp.org/usr_02.txt.html)。

遇到不知道自己处于什么状态的情况，先按 `Esc`。下面几条值得最先记住：

| 按键或命令 | 用途 |
|---|---|
| `i` | 在光标前开始输入 |
| `Esc` | 结束输入，回到按键操作的状态 |
| `:w` | 保存 |
| `:q` | 退出 |
| `:wq` | 保存并退出 |
| `:q!` | 强制退出，并放弃未保存修改 |

以冒号开头的命令都需要回车执行。出现 `E37: No write since last change` 时，是 Vim 提醒你有修改尚未保存。想保留就用 `:wq`，确定不要才用 `:q!`。

## 四种常用模式，先分清自己在做什么

普通模式用于移动、删除、复制等操作，是 Vim 的起始状态；插入模式用于输入文本；可视模式用于选择文本；命令行模式用于输入保存、替换等命令。

| 模式 | 怎么进入 | 做完以后 |
|---|---|---|
| 普通模式 | 从其他模式按 `Esc` 返回 | 可以继续移动或编辑 |
| 插入模式 | `i`，也可以用 `a`、`o` | 按 `Esc` 返回 |
| 可视模式 | `v` 按字符选择，`V` 按行选择 | 按 `Esc` 取消，或执行操作 |
| 命令行模式 | `:` | 回车执行，`Esc` 取消 |

`a` 是在光标后开始输入，`o` 是在当前行下方新建一行并开始输入。想在行尾补内容，用大写 `A`，可以少做一次移动。

先养成一个习惯：**输入完一小段，就按 `Esc` 回到普通模式。** 后面大多数命令都从这里开始。写中文时，回到普通模式后也要切回英文输入法，否则输入的可能是拼音，而不是 Vim 命令。

## 移动和修改，先掌握每天都用得到的

初学时可以继续用方向键，不必为了练 `hjkl` 停下正常工作。更值得练的是按词、按行、按搜索结果移动。

| 想去哪里 | 普通模式按键 |
|---|---|
| 左、下、上、右 | `h`、`j`、`k`、`l` |
| 下一个词的开头 | `w` |
| 上一个词的开头 | `b` |
| 当前词或下一个词的末尾 | `e` |
| 行首、行首第一个非空白字符、行尾 | `0`、`^`、`$` |
| 文件开头、文件末尾 | `gg`、`G` |
| 第 20 行 | `20G` 或 `:20` 后回车 |
| 向下移动 5 行 | `5j` |

这里的“词”由 Vim 的字符规则划分，不等同于中文分词，也不总等同于编程语言里的完整表达式。遇到标点较多的路径或表达式，可以以后再学大写 `W`、`B` 的空白分隔移动方式。

编辑时，先用下面几种操作：

| 想做什么 | 普通模式按键 |
|---|---|
| 删除光标处的字符 | `x` |
| 删除当前行 | `dd` |
| 复制当前行 | `yy` |
| 粘贴 | `p`；复制的是整行时，放到下一行 |
| 撤销 | `u` |
| 重做刚才撤销的修改 | `Ctrl+r` |
| 重复上一次可重复的修改 | `.` |
| 选择几行再复制 | `V`，用 `j` 或 `k` 扩大选区，再按 `y` |

Vim 的删除通常也会把内容存起来，因此 `dd` 后可以用 `p` 放到其他位置，相当于剪切再粘贴。字符级内容用 `p` 会放到光标后，整行内容则放到当前行下方。

不需要一次记完表格。先在练习文件里复制一行、删除一行、撤销一次，再回到自己的文件使用。

## 真正值得练的是“动作＋范围”

Vim 的命令可以组合。`d` 表示删除，`c` 表示修改，也就是删掉目标后进入插入模式，`y` 表示复制。给它们接上移动范围或文本对象，就能表达一次编辑。

文本对象是 Vim 识别的一块文本，例如一个词、引号内的内容、括号内的内容。下面这些组合比一长串快捷键更容易记：

| 命令 | 可以怎样理解 |
|---|---|
| `dw` | 从光标删到下一个词的开头，光标前面的字留着 |
| `d$` | 从光标处删除到行尾 |
| `ciw` | 修改光标所在的整个词 |
| `ci"` | 修改双引号里面的内容，保留引号 |
| `di(` | 删除所在括号内部的内容，保留括号 |
| `3dd` | 删除连续三行 |

组合里的 `i` 表示 inside，也就是“内部”，不是插入模式的 `i`。如果记不清移动范围，改词时先用 `ciw`，比把光标精确移到词首更省事。

比如有这样一行代码：

```java
String message = "hello world";
```

把光标移到字符串内部，依次按 `ci"`，输入 `Hello Vim`，再按 `Esc`，就会得到：

```java
String message = "Hello Vim";
```

如果下一行也有一个需要改成同样内容的字符串，把光标移到那对引号内部，再按 `.`，即可重复这次修改。这里省下的是重复定位、选择和输入的动作。

## 搜索和替换，先保证每次修改看得见

在普通模式输入 `/hello` 并回车，会向后搜索 `hello`。按 `n` 找下一个，按 `N` 往反方向找。`*` 可以搜索光标下的词，`:noh` 后回车可以暂时取消搜索高亮。

替换先用一个简单例子：

```vim
:%s/hello/Hello/gc
```

这里 `%` 表示整个文件，`s` 表示替换，`g` 表示处理一行里的所有匹配，`c` 表示每次先确认。遇到提示时，`y` 替换当前一处，`n` 跳过，`q` 停止。只处理当前行时，去掉 `%`。

Vim 搜索使用正则表达式，也就是可以描述匹配规则的模式，`.` 等字符可能有特殊含义。入门阶段先练普通单词，遇到路径、括号或复杂表达式再查转义规则，不要把任意文字原样塞进替换命令就批量执行。

**代码符号重命名优先用 IDE 的重构功能。** 文本替换只看匹配内容，IDE 能结合语言信息识别变量、方法和引用，更适合跨文件改名。

## 配置只加能解释清楚的几行

暂时不配置也能完成前面的练习。想让终端 Vim 更易读，可以把下面内容加入用户配置文件：macOS/Linux 常用 `~/.vimrc`，Windows 常用 `$HOME/_vimrc`。这里的配置路径是工具约定，已有文件时追加或合并，不要直接覆盖。

```vim
set number
set incsearch
set hlsearch
set ignorecase
set smartcase
syntax on
filetype plugin indent on
```

前三项是行号、输入时搜索预览和搜索结果高亮。`ignorecase` 配合 `smartcase` 后，全小写搜索通常忽略大小写，模式里有大写字母时区分大小写。最后两行开启语法高亮，并按文件类型加载插件和缩进。

缩进宽度和 Tab/空格习惯先跟项目走，不必立刻全局统一成四个空格。配色、状态栏和复杂插件可以等到日常编辑顺手以后再调整。

## 搭配 IDEA：保留开发环境，练习 Vim 编辑

已经在用 IntelliJ IDEA 写 Java，就可以把练习放进现有工作流。IdeaVim 是 JetBrains IDE 的 Vim 模拟插件，提供普通模式、文本对象等操作；代码补全、跳转、调试、测试和重构仍由 IDE 提供。

在设置里的 Plugins 搜索并安装 IdeaVim，按提示重启。可以通过 `Tools → Vim` 开关插件，在设置中搜索 Vim，处理快捷键冲突。配置使用 `~/.ideavimrc`，不能假设终端 Vim 的所有插件和选项都能照搬。[安装、配置与兼容范围见 IdeaVim 官方说明](https://github.com/JetBrains/ideavim)。

开始时只在代码编辑区练 `w`、`b`、`ciw`、`ci"`、`dd` 和 `u`。项目搜索、运行测试、重命名变量继续用熟悉的 IDEA 操作，遇到冲突就到 Vim/Keymap 设置里决定由谁处理，赶进度时也可以暂时关闭 IdeaVim。

熟悉以后，再把一两个常用 IDE 动作接到 Vim 键位。下面是可选的 `~/.ideavimrc` 示例：

```vim
set number
let mapleader = " "
nmap <leader>f <Action>(ReformatCode)
```

`leader` 是自定义快捷键的前缀，这里设为空格，因此普通模式下先按空格，再按 `f`，会调用 IDEA 的格式化代码动作。`<Action>` 是 IdeaVim 对接 IDE 的机制，这类映射按官方要求使用 `nmap`，不要机械地改成 `nnoremap`。需要更多动作时，可用 `:actionlist` 查找。[动作映射说明](https://github.com/JetBrains/ideavim#executing-ide-actions)

## 搭配 Claude Code：编辑提示词，也保留完整 Vim

Claude Code 可以在终端中接收任务、读取和修改项目文件。它与 Vim 的搭配有两个层次：输入框里的 Vim 键位，以及调用真正的外部编辑器。

### 在输入框使用熟悉的键位

当前官方文档给出的入口是 `/config → Editor mode`，选择 Vim。进入普通模式后，可以使用 `w`、`b`、`dd` 等支持的操作来修改提示词，按 `i` 回到输入状态。[Claude Code 交互模式文档](https://code.claude.com/docs/en/interactive-mode#vim-editor-mode)

这只是提示词编辑功能，不会把 Claude Code 变成完整 Vim，也不会让 `dd` 去删除项目文件中的一行。支持范围按官方键位表判断，不要默认 `:wq`、Vim 插件或 `.vimrc` 在这里生效。普通模式下的 `/` 是搜索历史命令，不是搜索这段提示词。`Ctrl+r` 也是历史搜索，不是重做。输入斜杠命令前先按 `i` 回到插入模式。

### 长提示词放进外部 Vim 编辑

在 macOS、Linux 或 WSL 的 shell 中，可以只为这次启动指定编辑器：

```bash
VISUAL=vim EDITOR=vim claude
```

在提示词输入区域按 `Ctrl+G`，Claude Code 会调用外部编辑器。完成编辑后，在真正的 Vim 中用 `:wq` 保存退出，回到 Claude Code 检查提示词，再发送。外部编辑器入口由 [Claude Code 官方交互说明](https://code.claude.com/docs/en/interactive-mode#general-controls)提供；这与上面的内置 Vim 模式是两套操作。

如果更喜欢先把任务写成文件，也可以用 Vim 编辑项目中的 `task.md`，然后让 Claude Code 阅读该文件。多段背景、限制条件和验收要求放在文件里，会比较容易反复修改。

### IDEA、IdeaVim 和 Claude Code 一起用

这三者可以各自承担一部分工作：IdeaVim 负责手动编辑时的键位，IDEA 负责语言分析和调试，Claude Code 负责你交给它的编码任务。

需要联动时，先安装 Claude Code CLI，再安装 JetBrains 的 Claude Code 插件。在 IDEA 的项目终端运行 `claude`；从外部终端启动时，可用 `/ide` 连接打开的 IDE。官方集成支持在 IDE 中查看修改差异和共享选区等上下文。[Claude Code 的 JetBrains 集成说明](https://code.claude.com/docs/en/jetbrains)

可以从一个很小的任务开始：

1. 在 IDEA 中打开一个函数，用 IdeaVim 阅读和做局部修改，然后保存。
2. 让 Claude Code 为这个函数补一个边界条件测试，说明希望覆盖的情况。
3. 在 IDEA 的差异视图里检查变动，运行测试，需要时打断点确认。
4. 用 IdeaVim 修正命名或注释，再审阅最终差异。

同一个文件尽量轮流修改，先保存自己的内容再交给 Claude Code，避免用编辑器里的旧内容覆盖外部更新。如果 IDEA 终端中的 `Esc` 被用于跳回编辑区，可在 Terminal 设置中调整相关焦点快捷键，官方集成文档也列出了这一问题。

## 提高和扩展：遇到什么需要，再补什么

日常操作熟悉以后，可以按需要继续学多文件、正则和编程支持。下面每一项都能单独练，不必把配置语言、补全和调试器一次学完。

| 遇到的需要 | 下一步学习 | 最小练习 |
|---|---|---|
| 来回改两个文件 | 缓冲区 | `:e other.txt` 打开文件，`:ls` 查看，`:bnext` 切换；切换前先保存 |
| 同时看两段内容 | 窗口 | `:vsplit other.txt` 左右分屏，`Ctrl+w` 后按 `w` 切换窗口 |
| 从 Vim 复制到其他应用 | 寄存器和系统剪贴板 | 选中文本后按 `"+y`；需要当前 Vim 和环境支持系统剪贴板 |
| 重复一串固定操作 | 宏 | `qa` 开始录到寄存器 a，操作一次后回普通模式按 `q`，再用 `@a` 回放 |
| 检查旧版和新版的差异 | Vim diff | 在终端运行 `vim -d old.txt new.txt`，先练阅读差异 |
| 偶尔补全长单词 | 内置补全 | 在插入模式按 `Ctrl+n`；它与 IDE 的语言智能补全不是一回事 |
| 文本乱码或换行异常 | 编码和文件格式 | 用 `:set fileencoding?`、`:set fileformat?` 查看，不急着转换 |

缓冲区是文件载入内存后的编辑内容，窗口是显示缓冲区的区域，标签页则可以容纳一组窗口。分屏之后 `:q` 只关闭当前窗口，最后一个窗口关掉才会退出。先学缓冲区和分屏，就能处理不少多文件任务，不必把每个文件都开成标签页。

宏适合规律明确的重复操作。先回放一次确认结果，再考虑多次执行；录制中的移动尽量依赖行首、词和搜索，减少依赖固定字符数量。系统剪贴板不可用时，可以先沿用终端自带的复制粘贴，不需要为一个命令立即更换整套环境。

补全插件、Vim 脚本和终端里的调试可以暂时放后面。日常已经依赖 IDEA 的补全与调试时，先使用现成能力；等到确实想在终端完成更多开发工作，再评估补全插件、语言服务器协议（LSP，用来让编辑器获取语言分析能力）或 Neovim。插件一次加一个，能说清它解决哪个问题再保留。

这些主题在 [Vim 用户手册目录](https://vimhelp.org/usr_toc.txt.html)里有对应章节。在本机也可以用 `:help windows`、`:help recording`、`:help clipboard` 查看帮助，`:q` 关闭帮助窗口。

## 一周练习，每次十到十五分钟

练习用小文件就够了。进度慢一点没有关系，第二天能在真实编辑中想起前一天的操作，比连续背一小时快捷键更有用。

| 时间 | 练习内容 | 完成标准 |
|---|---|---|
| 第一天 | 打开、输入、保存、退出 | 不查资料完成一轮 |
| 第二天 | `w`、`b`、`0`、`$`、搜索 | 定位一个词，不只靠方向键 |
| 第三天 | `dd`、`yy`、`p`、`u` | 用 `dd` 再 `p` 挪一行。按一次 `u` 只撤回粘贴，再按一次才回到挪动之前 |
| 第四天 | `ciw`、`ci"`、`.` | 修改两个字符串 |
| 第五天 | 带确认的替换 | 只替换自己确认的匹配 |
| 第六天 | 在 IdeaVim 或 Claude Code 中练习 | 完成一件小任务，辨认工具差异 |
| 第七天 | 回顾最常用的五个动作 | 留下自己的小抄，删掉暂时不用的配置 |

如果安装包带有 `vimtutor`，可以在终端运行它，直接在教程文本上练习。没有这个命令时，也可以用 `:help tutor` 查找当前安装的教程入口。

练到能独立改文件、找内容、撤销误操作，就可以把 Vim 放进日常工作了。下一条命令从下一次实际遇到的重复操作里找。
